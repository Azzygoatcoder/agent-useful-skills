## 新增 `SECURITY.md`

理由不是"别人都有"，而是**自相矛盾**：本仓库的旗舰技能就是 `code-security-audit`，它自己的「不算 Finding 判别表」会把"缺漏洞披露渠道"记成一条问题。安全工具仓库没有披露政策，是可信度上的硬伤。GitHub 也只有存在这个文件时才显示 **Report a vulnerability** 按钮。

内容刻意诚实：

- **不假装运营 PSIRT** —— 写明单人维护、**没有 SLA**、修复偏保守（本仓库的产物是**给 agent 读的指令**，改一句措辞的影响面比改一行代码更难评估）
- **划清范围**：你用本仓库技能审出来的、**别人项目里的**漏洞请报给那个项目；第三方技能报给各自上游；`plugins/superpowers/` 继承自上游的内容报给 obra/superpowers
- 点明这个仓库最隐蔽的一类问题：**工具给出的假保证**（校验器声称拦住了某件事、实际没拦 —— 用户会因此信任一个不成立的结论）。上一版修的 META-2 正是这一类

## 新增 `CONTRIBUTING.md`（索引，不是复述）

真正的问题不是"没人知道怎么 fork"，而是本仓库有若干 **CI 强制的隐性契约**散在 README / `VERSIONING.md` / `LICENSING.md` / `skeleton.md` / 三份 `CLAUDE.md` 里 —— 不知道的人（或 agent）只会拿到一个**看不懂的红 CI**。

所以它写成「**规则 → 权威文档**」的索引，并明确声明：

> **若本页与链接文档不一致，以链接文档为准** —— 重述必然漂移。

另含：本地门禁命令、三条最容易踩的（技能目录必须单层 / `description` 有 500 上限且它就是触发词 / `## 自进化日志` 必备 + 归档而非删除）、PR 期待，以及**这个仓库大概不会合的东西**（纯格式化全仓库重排、与现有技能高度重叠的新技能、"第二份真相"式结构）。

## 新增 `.github/dependabot.yml`（只配 `github-actions`）

**刻意窄范围**，文件注释里写清了为什么排除另两个生态，免得后人「顺手补上」：

- **npm 不加**：唯一依赖 `@deepseek-ai/dsh-skill-filesystem` 是 caret 范围，且仓库里**没有提交 lockfile**（`.gitignore` 明确忽略 `package-lock.json` —— 这些 node 依赖只服务于本地/CI 的插件校验）。范围本就浮动到最新兼容版，再提一个「调高下限」的 PR 近乎无意义
- **pip 不加**：Python 依赖全是**可选 extras** + 宽松 `>=` 下限（"核心命令零第三方依赖"），CI 本身只用标准库

`github-actions` 才是真有价值的：工作流按**大版本 tag** 固定（`actions/checkout@v7` 之类），dependabot 会在上游发大版本时提 PR。按月分组，一次 PR 覆盖全部 action。
