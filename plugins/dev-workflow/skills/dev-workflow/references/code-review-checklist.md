# Code Review Checklist — 通用代码质量评审

场景 B（评审代码）与流程第 2 步用这份清单**就地**评审，不需要任何外部 skill。
四类各扫一遍，发现项按严重度排列；**只报能说清「为什么是问题 + 怎么改」的条目**，不凑数。

## 1. 找 Bug（最高优先）

| 检查 | 典型形态 |
|------|---------|
| 边界 | 空集合 / 单元素 / 越界索引 / 0 与负数 / 首末元素 |
| 空值 | `None`/`null`/`undefined` 未判就解引用；可选字段直接 `.` 链 |
| 并发 | 共享可变状态无锁；先查后写（TOCTOU）；迭代中修改集合 |
| 错误处理 | 吞异常（`except: pass`）；`return` 与 `raise` 混淆；错误码当成功用 |
| 资源 | 文件/连接/句柄未关（缺 `with`/`defer`/`finally`） |
| 类型 | 隐式转换丢精度；字符串与数字比较；`==` 与 `===` |
| 异步 | 未 await 的 promise/future；阻塞调用出现在事件循环里 |
| 路径 | 字符串拼接路径；用户输入直接进路径（穿越）；`..` 未规范化 |

## 2. 复用

- 同一段逻辑出现第 3 次 → 抽函数/模块
- 仓库里**已有**等价实现却新写了一份 → 指向既有实现
- 复制粘贴产生的近似重复（差异只在常量/字段名）
- 重新实现了标准库 / 已有依赖已提供的功能

## 3. 简化

- 参数过多的函数（>5）→ 收成结构体/对象
- 嵌套过深（>3 层）→ 卫语句提前返回
- 死代码、不可达分支、注释掉的旧实现
- 过度抽象：只有一个实现的接口、只转发不加工的包装层
- 命名与行为不符（`get_` 却改状态、`is_` 却返回值）

## 4. 效率

- 循环内重复计算不变量；循环内做 I/O 或查询（N+1）
- 该批量却逐条处理；该索引却线性扫描大集合
- 不必要的全量拷贝（大列表/大字典浅拷贝仍需遍历）
- 频繁拼接字符串/数组增长未预留
- 热点路径上的正则重复编译

## 输出格式

按严重度分组，每条给：**位置（file:line）→ 问题 → 为什么是问题 → 建议改法**。

```
## 必须改（bug / 数据风险）
- `src/loader.py:42` 路径直接拼接用户输入，`../` 可穿越出数据目录；
  改用 `Path(base, name).resolve()` 并断言前缀在 base 内。

## 建议改（复用 / 简化 / 效率）
- `src/report.py:88-130` 与 `src/export.py:20-60` 表格渲染逻辑重复；
  抽 `render_table(rows, cols)` 供两处调用。
```

## 边界

- **不做安全审计**：漏洞、注入、鉴权、密钥 → 走 `code-security-audit`（本清单只管通用工程质量）
- **不替代测试**：发现项要能被测试覆盖的，指出该补哪个用例，而不是断言"应该没问题"
- 拿不准的写"待确认"并说明需要什么信息，不要猜
