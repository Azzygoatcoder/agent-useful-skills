# 补充攻击面域（五域）

> **懒加载 reference：不要整篇读。** 只读边界侦察（Phase 1）真正命中的那一个域，其余四节不要打开。
> 这五个域是主流程三个域 agent（secrets / injection / auth-crypto-deps）**不覆盖**的攻击面，属补充展开，不是默认清单。
> 每域只有三段：何时用 / 类清单 / 不算 finding；类清单给的是可 grep、可追踪的检查点，不是背景知识。
> 判定顺序：先用「何时用」确认边界真实存在，再读类清单；域没打开就不要引用它的类目。

---

## ① AI / LLM / Agent 目标

**何时用**

代码里存在「不可信内容 → 模型或记忆 → 能力、权限或 sink」这条数据流时适用：检索/摄取入库、会话与持久记忆读写、工具分发、MCP 客户端、模型输出渲染。传输、鉴权、查询构造、文件系统、输出渲染本身仍走普通域。

**类清单**

- 间接注入——RAG 文档、索引页、上传文件、issue 正文、工具返回、元数据里的内容，是否进入另一个主体的上下文或触发其本无权触发的动作；字符串拼接、无类型 history、调用方可控 role 字段、序列化往返丢掉 source 标签都属这一类。
- 跨会话/跨租户上下文渗漏——history、embeddings、检索结果、prompt cache 的 key 是否过宽；ACL 过滤要既在查询里，也在每一个 cache key 里。
- 持久记忆投毒——谁能 create/update/merge/delete memory；低可信来源的观察是否升级成持久指令；provenance 与 tenant scope 是否随写入保存并可读回。
- 工具参数注入下游 sink——tool schema 只是输入解析，**不建立**鉴权、safe path、safe URL 或查询语义；别名、多余字段、重复 key、类型强转、越界值在「取值变成资源选择器」处要重新校验。
- 过度代理 / 混淆代理——handler 以服务身份执行却不按被点名的资源复核请求者权限；对照调用方走正常产品接口本来能做到什么。
- 动作确认绑定与 MCP 标识混淆——确认对象须绑定归一化工具名 + 完整参数 + 请求者 + 目标 + 额度 + 过期 + 批次；按可被影响的 server/tool 名、request id、resource URI 或模型选出的别名路由（而非已认证连接 + 未决请求）同属此类，子代理不得继承整会话凭证与能力。

**不算 finding**

- 单有 prompt injection 不算——必须指到代码级边界失败：内容进入另一主体上下文、调用了请求者本没有的权限、泄露读不到的数据、驱动不可达 sink。
- guardrail prompt / system prompt 不算安全边界；只数确定性检查、按资源鉴权、隔离、绑定、受限凭证。
- 记忆或检索类主张要同时给出攻击者可控的写入与之后一次跨主体读取，缺一半即不成立。

## ② 供应链 / CI / 发布

**何时用**

仓库里存在依赖解析、CI 与工作流定义、构建与发布产物、签名与推广、更新器或插件安装这些「源码/依赖 → 用户实际运行的产物」信任交接点时适用。判断依据是交接点，不是语言名或某个依赖名。

**类清单**

- 依赖命名空间/解析源混淆——resolver 是否可能选中非预期的 public/private 命名空间、fallback registry、mirror 或 source URL；lockfile 与 checksum 是否真被消费。
- 可变/未绑定的构建输入与构建上下文夹带——分支、tag、未校验 submodule、下载的工具、浮动 action、容器 tag；以及密钥、本地配置、repo 元数据、测试 fixture 是否经 build context 与 ignore 规则进入包或镜像。
- CI 里跑不受信代码——PR、issue 评论、fork、依赖更新等事件是否让贡献者代码拿到受保护 secret、write token、发布权限或可信 runner；分支名、提交信息、issue 字段、artifact 名是否又进入 shell、模板表达式或特权 workflow 输入。
- 缓存/artifact/workspace 信任混用——低可信 job 写入的 cache、artifact 或共享 workspace 是否被高可信 job 恢复后执行或发布；看 cache key、生产者身份、digest 绑定、按可变名重新解析的 promotion。
- 构建到发布的标识替换——测试、评审、签名、发布是否指向可变 tag/文件名/channel，而非同一个不可变 digest；中间每次 copy、repack、架构合并都是交接点；签名是否来自错误的 workflow、仓库、分支或密钥角色，失败与回滚是否 fail closed。
- 插件/扩展信任扩张与更新器绑定——扩展包是否取得超出声明范围的主机权限、低可信发布者能否替换他人身份、安装/更新 hook 是否在真实性与能力检查之前运行；更新器是否只验字节而不绑定 version/product/platform/channel/target path/过期/回滚状态。

**不算 finding**

- 有个有漏洞的依赖本身不算——要证明谁能影响解析、哪个构建消费它、之后跨了哪个执行或发布边界。
- 缺 least-privilege、分支保护、托管 runner、registry、签名服务的默认值属 needs_validation（源码不可见），不要当结论报。
- 与产物取自同一不可信位置的 checksum 不建立独立完整性；须先指出可信根与失败行为。

## ③ 桌面 / 移动 / 本地 IPC

**何时用**

存在桌面或移动应用、特权 helper、更新器、本地守护进程、webview 宿主、深链处理器、native messaging 宿主或本地 IPC 端点时适用。先声明攻击者的起始能力（被打开的文档、远端 web 内容、另一个本地应用、另一个 OS 用户、沙箱进程），不要把「本地用户」视为等价。

**类清单**

- 自定义 scheme 与深链歧义——能改状态、导入数据、完成认证或选择账号的路由，是否绑定当前会话与一次性回调；看 URI 归一化、重复 query 字段、scheme/host/path 匹配、导出 handler 策略、过期与重放链接。
- 文件打开与 intent 权限混淆——文件关联、分享 intent、拖放、剪贴板、通知动作是否在缺少内容类型、发送者信任、当前 intent 与最终目标校验的情况下触发特权操作。
- webview 导航后 origin 漂移与 bridge 能力过宽——远端 frame 是否触到本应只给打包内容的 bridge；origin 要在调用时以及每次导航、重定向、子 frame、弹窗、错误页之后校验，URL 前缀与首载检查都不够；通用 bridge 是否暴露任意文件、命令、IPC 方法、凭证或系统动作。
- 本地 IPC 对端鉴权缺失——Unix socket、命名管道、XPC、Binder、D-Bus、native messaging、loopback 监听是否接受低可信对端；必须用 OS 对端凭证、代码身份、沙箱 token 或通道所有权，而不是路径、进程名、bundle/package ID 或自称 sender 字段。
- 导出组件过宽与特权 helper 混淆代理——外部可调用的 service/activity/receiver/provider 是否在做只该应用自己做的事（要看最终合并后的 manifest、intent filter、权限级别、路径授权与别名）；helper 是否让低可信调用者选择特权命令、文件、服务、用户或系统设置，且未独立校验归一化后的参数与最终目标。
- 安装/更新路径信任与账号残留——特权安装器读取的 manifest、脚本、包、符号链接、工作目录、修复状态是否在授权之后仍可被低可信者改写；本地数据库、webview storage、通知、待处理动作与生物识别授权是否跨登出、切号或备份恢复存活。

**不算 finding**

- 同一账号、同一权限内的自我伤害不算边界跨越；先声明攻击者起始能力。
- 路径、进程名、bundle/package ID、自称 sender 字段都不算对端认证；打包、签名、entitlement 不可见时归 needs_validation。
- 本地明文凭证若只有目标 OS 账号可读、且不存在更低权限读者，不算漏洞。

## ④ 资源耗尽 / 可用性

**何时用**

不可信输入能消耗共享 CPU、内存、磁盘、连接、worker 槽、付费 API 或队列容量，或能让共享服务死锁/崩溃时适用。判定要同时具备输入→成本路径、缺失的有效上界、对他人或共享服务或运营方开销的影响。

**类清单**

- 超线性解析、匹配与求值——灾难性正则回溯、嵌套解析、递归校验、符号求值、图遍历、模板展开、对抗性排序或哈希；先取被接受的深度与基数，再用有界增长曲线证明。
- 解压与表示放大——压缩、稀疏、嵌套、别名或编码输入在已检查的传输/文件大小之外膨胀；限制要在每次展开之后、以及每个解析阶段都验证。
- 无界缓冲、基数与句柄泄漏——body、乱序流、上传、会话、唯一 cache key、指标 label、订阅、待处理任务是否清理（断开、超时、取消、部分解析路径）；socket、文件、DB cursor、定时器、子进程在畸形或取消路径上是否残留并用有界迭代耗尽共享池。
- 取消后仍在跑的工作与认证前的高成本工作——客户端超时或断开、任务取消、鉴权失败之后，DB/模型/网络/worker 工作是否继续（追踪取消与 deadline 在各层的传播）；昂贵解析、key 查找、加密、解压是否发生在认证之前以及最早的大小或速率门之前。
- 配额记账范围与重置缺口——记账键是否建立在可被影响的 IP、路由、租户、key 前缀、task ID 上；溢出、分布式竞态、重试、重连、切号是否让一方逃出预算或消耗他人额度；低优先级或攻击者可控的 job 是否长期占用共享锁、worker、DB 连接池、事件循环或调度优先级。
- 可达的致命错误、死锁与恢复放大——不可信输入是否触达 panic/abort/未捕获异常/进程退出/锁环；无抖动无上限的重试风暴，以及队首毒消息在同一分区反复失败。

**不算 finding**

- 缺 rate limit 本身不算——先查 body/消息/文件上限、并发、队列、deadline、DB 约束、上游网关、按租户配额。
- 只在请求者自己进程内自我限制的工作不算服务漏洞；缺上界但没有具体共享影响属 hardening。
- 不要通过压测共享或线上服务验证；用渐近分析、小边界 fixture、mock 付费调用、严格本地限额。

## ⑤ 数据隔离 / 生命周期

**何时用**

存在多租户或受访问控制的存储，以及由它派生的副本（缓存、搜索索引、分析/日志、导出/备份、删除/吊销、迁移）时适用。端点级访问控制仍归普通域，provider 侧存储策略归 cloud 域。

**类清单**

- 缺租户/属主约束与复合键碰撞——read/update/delete/list/count/bulk 是否把对象绑定到已认证的租户或属主，还是信任 body 字段（对照直接查找、嵌套关系、后台任务、admin、导入、legacy 路径）；cache key、对象路径、DB 唯一约束、搜索 doc ID、临时文件、去重键是否漏掉租户或环境。
- 策略与查询不一致——行级策略 vs ORM 默认作用域 vs 鉴权过滤器 vs 原生或绕过客户端；看 join、聚合、别名、视图、事务、unscoped/service client、以及 context 缺失的错误路径。
- 缓存与搜索索引的 ACL 漂移——ACL 或生命周期变更是否使搜索、缓存、内嵌、缩略图、RSS、预览、索引副本失效；入库、取值、失效三处都要校验过滤。
- 导出、备份与导入的范围/权限扩张——导出是否带出其他租户、不可访问字段、软删数据、密钥值、超出请求者权限的历史（逐项鉴权要在选取之后，产物本身下载权限也要查）；导入是否绕过属主、schema、ACL、唯一性、校验，覆盖既有资源或在不可写租户里重建记录 —— 归档内容按不可信处理，并对结果操作重新鉴权。
- 迁移默认值与软删绕过——旧记录缺租户/ACL/生命周期字段、ID 冲突、新旧读者应用不同默认值的部分灰度（看 backfill、双读双写、兼容、回滚、续跑）；直接查找、搜索、关系遍历、对象链接、后台处理器、restore 是否忽略生命周期谓词，软删标识符能否被重新注册。
- 陈旧授权、派生副本与保留期越界——成员移除、ACL 更新、同意撤回、密钥吊销、角色降级是否让会话、cache、订阅、任务、物化数据失效；主记录删除后队列处理器、重试、导出、分析是否重建或继续保留；恢复是否重新引入当前策略禁止的数据、凭证、成员关系或权限。

**不算 finding**

- 记录上「有」tenant/owner 字段不算隔离——要找到每次读写真正生效的 query、key、path、policy 或行级控制。
- 隐私或保留偏好本身不算漏洞；需要一个明确的数据访问边界或删除/吊销保证，加一个未授权读者或后续操作。
- 字段名、公开标识符、按既定策略可见的运营者内容不算泄露；派生副本主张要指到具体副本与它不同的 ACL 或保留。

## 与现有三域的关系

- 这五域是**补充**：默认常开扫描仍是现有三个 agent（secrets / injection / auth-crypto-deps），本文件不替换它们，也不并入默认清单。
- 每个域只在侦察**确实发现了它的边界**时才打开，绝不「以防万一」；没命中的域记为 excluded 并写明排除理由。
- 与主清单重叠处按边界归属切分：端点级访问控制、传输、查询构造、文件系统、输出渲染仍走普通域，本文件只处理上面写的那些边界。
- 本文件是提示词素材，不是覆盖证明：读过一个域不等于审过。
